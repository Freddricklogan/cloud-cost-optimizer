# AUDIT — Cloud Cost Optimizer (pre-refactor)

Audit of the previous build: one 305-line `index.html` with the markup,
the CSS and a 186-line inline script; no data files, no tests, no CI.
Thirty-one resources with a monthly cost and a utilisation number were
typed into the script; every headline figure was a constant or a
constant multiplied by the total. Line numbers refer to the old file.

---

## A. Honesty of the copy

### A1 — "+8.3% vs last month" was a string literal
Line 185: `textContent='+8.3% vs last month'`. There was no last month;
the page held one number per resource. **Fix:** month-over-month is
computed from the two most recent *complete* months of the FOCUS
export; when there are not two, the tile says so.

### A2 — "Potential savings" was 28 % of whatever the total was
Line 181: `potentialSavings=Math.round(totalCost*.28)`. The savings
tile, its percentage, and the six-month "cumulative savings" chart
(line 220: `potentialSavings*(i+1)*0.15*(1+i*0.1)`) all derived from that
constant. **Fix:** identified savings are the sum of the recommendation
lines, each of which is arithmetic on an observed run rate and a named
assumption shown next to it. No projection chart is drawn from a
constant.

### A3 — A "cost trend" drawn from `Math.random`
Line 207: `totalCost*(0.82+i*0.04+Math.random()*0.03)` produced a
different six-month history on every click. **Fix:** the monthly and
daily charts are sums of the rows; partial months are starred.

### A4 — Recommendation percentages with no source
Idle 70 %, storage tiering 45 %, reserved 35 %, right-sizing 30 %, spot
70 %, network 25 % (lines 246–271): six constants dressed as analysis.
**Fix:** idle saving is the full run rate (removal); right-sizing uses
one explicit assumption (one size step halves the price) and fires only
when the utilisation after the step stays under a target; commitment
discounts are inputs labelled as assumptions with placeholder defaults;
egress is reported as an observation with measured numbers and no
saving; storage tiering and spot are not claimed because the data
cannot support them.

### A5 — "1-Year RI Cost" and "3-Year RI Cost" columns
Lines 292–293: `ri1=cost*.65`, `ri3=cost*.45` presented as reserved-
instance prices. **Fix:** replaced by the editable discount inputs and a
basis line on every commitment recommendation.

## B. Correctness

### B1 — Utilisation and cost were single numbers, not series
Nothing could be trended, forecast or flagged. **Fix:** the input is a
FOCUS 1.0 export (one row per resource per charge period); the sample is
183 days × 31 resources, generated by a seeded script and labelled
synthetic on the page.

### B2 — Idle detection ignored the window
`r.util<20` on a single value. **Fix:** mean of the last 14 days'
`x_UtilizationPct`, threshold editable, resources without utilisation
(storage, networking, serverless) are never called idle.

### B3 — Right-sizing table showed a size with no check that it fits
Line 285: any resource under 50 % got the next size down and a 35 %
saving. **Fix:** `stepDown()` knows AWS, Azure and GCP naming, returns
`null` at the smallest size, and the recommendation requires
`utilisation ÷ ratio ≤ target`.

### B4 — Budget bar clamped at 100 %
Line 189: `Math.min(…,100)`; an overspend could not be displayed.
**Fix:** budget use shows the projected month-end over the budget,
coloured past 90 % and past 100 %.

### B5 — Provider comparison ignored the filter
Lines 212–214 always summed all three providers whatever the buttons
said. **Fix:** every panel is computed from the filtered rows.

## C. Security and structure

### C1 — No CSP, five `onclick`, one `onchange`, 17 `style=`, 4 `innerHTML`
Handlers relied on the deprecated global `event` (line 174). **Fix:**
`default-src 'none'` with a script allow-list; `addEventListener`;
classes; `textContent` and `el()`. An uploaded CSV is untrusted input
and never reaches `innerHTML`.

### C2 — Chart.js without SRI
Line 7. **Fix:** integrity hash computed against the artifact plus a
vendored fallback.

## D. Engineering

### D1 — No import, no export, no tests
**Fix:** FOCUS import with per-row validation and a warnings panel;
recommendations CSV and summary JSON export; 21 Vitest tests over
ingestion (including rejected rows), aggregation reconciliation,
forecast, anomalies, right-sizing rules and assumptions; ESLint,
html-validate, security scan and Pages deployment in CI.
